General notes

  1. CoreDataType is TflOmniDb's provider-neutral type enum (Core/CoreDataType.cs); the per-provider type mappers translate it to the native types in each column. '(none)' marks a SQL Server type with no canonical CoreDataType - map it to the nearest enum value, or set a per-column native override.
  2. Per-column overrides exist via the [DbColumn] SqlServerType / OracleType / PostgresType escape hatches for the rare native-type need.
  3. Money is deliberately NUMERIC(19,4) on all three engines - PostgreSQL's MONEY type is locale-dependent and unsafe for financial code.
  4. Identifier casing: Oracle folds unquoted identifiers to UPPER, PostgreSQL to lower. Quote consistently, or pick one case across the schema.
  5. Oracle DATE always carries a time component (to seconds). Use TIMESTAMP for fractional seconds; for pure dates, enforce truncation in the app.
  6. Booleans: target Oracle <23c as NUMBER(1) with 0/1 values; Oracle 23c+ and PostgreSQL have a native BOOLEAN.
  7. Auto-increment: PostgreSQL and Oracle 12c+ support GENERATED ... AS IDENTITY; older Oracle needs a SEQUENCE + trigger.
  8. Row versioning: there is no portable equivalent to SQL Server ROWVERSION. Use an app-managed integer version column (TflOmniDb IsRowVersion) checked in the UPDATE WHERE clause; Oracle ORA_ROWSCN / PostgreSQL xmin are not drop-in replacements.
  9. LOBs map (N)VARCHAR(MAX)/VARBINARY(MAX) -> Oracle CLOB/NCLOB/BLOB -> PostgreSQL TEXT/BYTEA.
  10. PostgreSQL is UTF-8 native, so NVARCHAR and VARCHAR both collapse to VARCHAR/TEXT; JSONB beats JSON for indexing (GIN); BYTEA covers all binary widths.
