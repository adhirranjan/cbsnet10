General notes
-------------
1. CoreDataType is TflOmniDb's provider-neutral type enum (Core/CoreDataType.cs); the per-provider type mappers translate it to the native types in each column. '(none)' marks a SQL Server type with no canonical CoreDataType - map it to the nearest enum value, or set a per-column native override.
2. Per-column overrides exist via the [DbColumn] SqlServerType / OracleType escape hatches for the rare native-type need.
3. Money is deliberately NUMBER(19,4) to match SQL Server's NUMERIC(19,4) for financial code.
4. Identifier casing: Oracle folds unquoted identifiers to UPPER. Quote consistently, or pick one case across the schema.
5. Oracle DATE always carries a time component (to seconds). Use TIMESTAMP for fractional seconds; for pure dates, enforce truncation in the app.
6. Booleans: target Oracle <23c as NUMBER(1) with 0/1 values; Oracle 23c+ has a native BOOLEAN.
7. Auto-increment: Oracle 12c+ supports GENERATED ... AS IDENTITY; older Oracle needs a SEQUENCE + trigger.
8. Row versioning: there is no Oracle equivalent to SQL Server ROWVERSION. Use an app-managed integer version column (TflOmniDb IsRowVersion) checked in the UPDATE WHERE clause; ORA_ROWSCN is not a drop-in replacement.
9. LOBs map (N)VARCHAR(MAX)/VARBINARY(MAX) -> Oracle CLOB/NCLOB/BLOB.
10. Oracle RAW columns cap at 2000 bytes; use BLOB for larger binary. VARCHAR2 caps at 4000 bytes (32767 with extended string types).
