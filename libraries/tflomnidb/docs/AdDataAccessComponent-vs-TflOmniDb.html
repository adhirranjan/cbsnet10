AdDataAccessComponent vs. TflOmniDb

A side-by-side comparison of the legacy VB.NET data-access component (Enterprise Library 5.0, static API, sync-only) and its modern replacement (net10 / net48, instance API, async-only, SQL Server + Oracle + PostgreSQL).

Legacy: VB.NET · EntLib 5.0 · SQL Server + Oracle New: C# · .NET 10 + net48 · 3 providers · async Companion: Migration-from-AdDataAccessComponent.md

3.Side-by-side code, feature by feature

Same fictional table throughout: DemoWidget (Id identity PK, Name, Price, Notes). Left pane: legacy VB.NET. Right pane: TflOmniDb C#.

3.1 Entity definition

Legacy — VB.NET (class name IS the table name)
' Every property must carry the attribute — the DAL reads
' GetCustomAttributes(True)(0) blindly.
Public Class DemoWidget
    Inherits AdEntity

    Private _id As Integer?
    <AdDbColumnInfo(IsPrimaryKey:=True, IsAutoIncrement:=True,
                    DbType:=DbType.Int32, DataType:=GetType(Integer),
                    AllowDbNull:=False)>
    Public Property Id() As Integer?
        Get
            Return _id
        End Get
        Set(ByVal value As Integer?)
            _id = value
        End Set
    End Property

    '... same Get/Set boilerplate for Name, Price, Notes
End Class
TflOmniDb — C# (explicit table name; scaffolder-generated)
[DbTable(TableName = "DemoWidget")]
public class Widget : Entity
{
    [DbColumn(ColumnName = "Id", CoreType = CoreDataType.Int64,
        AllowDbNull = false, IsPrimaryKey = true,
        KeyGeneration = KeyGenerationStrategy.Identity)]
    public virtual long? Id { get; set; }

    [DbColumn(ColumnName = "Name", CoreType = CoreDataType.UnicodeString,
        Size = 100, AllowDbNull = false)]
    public virtual string? Name { get; set; }

    [DbColumn(ColumnName = "Price", CoreType = CoreDataType.Money,
        AllowDbNull = false)]
    public virtual decimal? Price { get; set; }

    [DbColumn(ColumnName = "Notes", CoreType = CoreDataType.UnicodeString,
        Size = 500, AllowDbNull = true)]
    public virtual string? Notes { get; set; }
}

3.2 Setup / connection

Legacy — nothing to construct; config is ambient
' Connection from app.config (EntLib DAAB section), or per call:
Dim connInfo As New AdConnectionInfo("MainDb")            ' config name
Dim connInfo2 As New AdConnectionInfo(cs,
    "System.Data.SqlClient")                              ' string+provider
TflOmniDb — construct once, reuse (DI-friendly)
var data = new DataAccess(new DataAccessOptions
{
    Provider = DbProvider.SqlServer,   // or Oracle / PostgreSql
    ConnectionString = cs,
    DefaultSchema = "dbo",
    CommandTimeoutSeconds = 60,
});
var repo = data.Repository<Widget>();

3.3 Insert (identity round-trip)

Legacy — ByRef Integer (Int32 only)
Dim w As New DemoWidget With {.Name = "gear", .Price = 25D}
Dim newId As Integer
AdDataAccessComponent.Insert(w, newId)
' w.Id is NOT populated — only newId is.
TflOmniDb — key written back into the entity
var w = new Widget { Name = "gear", Price = 25m };
await repo.InsertAsync(w);
Console.WriteLine(w.Id);   // populated

3.4 Update — full row

⚠ Semantics differ. Legacy skips properties that are Nothing (implicit partial update). TflOmniDb writes every updatable column — a null property becomes NULL in the database. Audit legacy Update call sites before porting.
Legacy — null properties are silently skipped
w.Name = "gear v2"
w.Price = Nothing          ' stored PRICE left untouched
Dim rows As Integer = AdDataAccessComponent.Update(w)
TflOmniDb — full row, or explicit partial
w.Name = "gear v2";
int rows = await repo.UpdateAsync(w);   // writes ALL columns

// keep the legacy "only these columns" behavior explicitly:
await repo.UpdateAsync(w, x => x.Name); // partial (net10)

3.5 Set-based update by criteria

Legacy — raw string concatenated into SQL (injection risk)
AdDataAccessComponent.Update(w, "PRICE < 50")
TflOmniDb — translated, parameter-bound
await repo.UpdateWhereAsync(
    x => x.Price < 50m,
    [ (x => x.Notes, "on sale") ]);

3.6 Delete

Legacy
AdDataAccessComponent.Delete(w)                    ' by PK
AdDataAccessComponent.Delete(w, "NOTES IS NULL")   ' by criteria
TflOmniDb
await repo.DeleteAsync(w);                         // by PK
await repo.DeleteWhereAsync(x => x.Notes == null); // by predicate

3.7 Get by key

Legacy — Object return, caller casts; id formatted into WHERE
Dim w As DemoWidget = CType(
    AdDataAccessComponent.RetrieveByKey(GetType(DemoWidget), 42),
    DemoWidget)
TflOmniDb — typed, parameter-bound
Widget? w = await repo.GetAsync(new object[] { 42L });

3.8 Retrieve all / filtered list

Legacy — raw criteria; Object → cast
Dim all As List(Of DemoWidget) = CType(
    AdDataAccessComponent.Retrieve(GetType(DemoWidget)),
    List(Of DemoWidget))

Dim dear As List(Of DemoWidget) = CType(
    AdDataAccessComponent.Retrieve(GetType(DemoWidget),
        "PRICE > 100"),
    List(Of DemoWidget))
' No ordering or paging support.
TflOmniDb — typed; predicate; ordering + paging built in
IReadOnlyList<Widget> all  = await repo.GetAllAsync();
IReadOnlyList<Widget> dear =
    await repo.WhereAsync(x => x.Price > 100m);

// no legacy equivalent — ordered page 3 (20 rows/page):
var page = await repo.WhereAsync(x => x.Price > 0m,
    orderBy: x => x.Name, descending: false,
    skip: 40, take: 20);

3.9 Count & aggregates

Legacy — Int32 only; criteria strings; no Sum/Avg/Exists
Dim n   As Int32 = AdDataAccessComponent.Count(
    GetType(DemoWidget), "PRICE > 100")
Dim max As Int32 = AdDataAccessComponent.Max(
    GetType(DemoWidget), "Price", "PRICE > 0")
Dim top As Int32 = AdDataAccessComponent.MaxPrimaryKeyValue(
    GetType(DemoWidget))
TflOmniDb — typed results, optional predicate
long     n   = await repo.CountAsync(x => x.Price > 100m);
decimal? max = await repo.MaxAsync<decimal?>(
                   x => x.Price, x => x.Price > 0m);
long     top = await repo.MaxKeyAsync<long>();
decimal  sum = await repo.SumAsync<decimal>(x => x.Price) ?? 0m;
bool     any = await repo.AnyAsync(x => x.Price > 999m);

3.10 Raw SQL

Legacy — DataSet out; no parameter support on Select()
Dim ds As DataSet = AdDataAccessComponent.Select(
    "SELECT Name, COUNT(*) AS N FROM DemoWidget GROUP BY Name")
For Each dr As DataRow In ds.Tables(0).Rows
    Console.WriteLine("{0}: {1}", dr("Name"), dr("N"))
Next
TflOmniDb — typed POCO or dict rows; parameters bound
public sealed class NameCount { public string? Name; public int N; }

var rows = await data.QueryAsync<NameCount>(
    "SELECT Name, COUNT(*) AS N FROM DemoWidget " +
    "WHERE Price > @p GROUP BY Name",
    new Dictionary<string, object?> { ["@p"] = 10m });

// untyped alternative + null-safe getters:
var dicts = await data.QueryAsync(
    "SELECT Name, COUNT(*) AS N FROM DemoWidget GROUP BY Name");
foreach (var r in dicts)
    Console.WriteLine($"{r.GetString("Name")}: {r.GetInt32("N")}");

3.11 Stored procedure (inputs, OUT param, result set)

Legacy — dict in, DataSet out; params auto-discovered (extra round-trip)
Dim params As New Dictionary(Of String, Object)
params.Add("@FromAccount", 1001)
params.Add("@Amount", 500D)
params.Add("@NewBalance", 0D)              ' OUT

Dim ds As DataSet =
    AdDataAccessComponent.Execute("usp_Transfer", params)
Dim bal As Decimal = CDec(params("@NewBalance"))
TflOmniDb — explicit fluent declaration; typed result
var call = new StoredProcedureCall("usp_Transfer")
    .Input("FromAccount", 1001)
    .Input("Amount", 500m, CoreDataType.Money)
    .Output("NewBalance", CoreDataType.Money);

StoredProcedureResult r = await data.ExecuteProcedureAsync(call);
decimal bal  = r.GetOutput<decimal>("NewBalance");
var     rows = r.FirstResultSet;   // ColumnNames + Rows

3.12 Transactions

Legacy — hand-thread the transaction into every call
' Miss one call and that write silently escapes atomicity.
' (And TransactionManager.Rollback() actually COMMITS — a bug.)
Dim tm As New TransactionManager()
Dim tx As DbTransaction =
    CType(tm.BeginTran(connInfo), DbTransaction)
Try
    AdDataAccessComponent.Insert(w1, tx)
    AdDataAccessComponent.Update(w2, tx)
    tm.Transaction = tx
    tm.Commit()
Catch
    ' manual cleanup...
End Try
TflOmniDb — unit of work; auto-rollback on dispose
using (var uow = await data.BeginTransactionAsync())
{
    var r = uow.Repository<Widget>();
    await r.InsertAsync(w1);
    await r.UpdateAsync(w2);
    await uow.CommitAsync();
}   // exception before CommitAsync ⇒ automatic rollback

3.13 Command timeout

Legacy — per call via the options bag (simple overloads: none)
Dim options As New AdDataAccessOptions()
options.Entity = w
options.CommandTimeout = 300
AdDataAccessComponent.Update(options)
TflOmniDb — instance default + per-scope override
// instance default (also bindable from appsettings.json):
CommandTimeoutSeconds = 60,

// per-scope override, just for one slow operation:
using (data.UseCommandTimeout(300))
{
    var report = await data.QueryAsync<NameCount>(heavySql);
}   // reverts on dispose; 0 = no timeout

3.14 Net-new in TflOmniDb (no legacy code to compare)

TflOmniDb — capabilities with no legacy counterpart
// Bulk insert — orders of magnitude faster than a loop for large batches.
await repo.BulkInsertAsync(widgets, new BulkInsertOptions { BatchSize = 5_000 });

// Streaming read — O(1) memory over any row count (net10).
await foreach (var w in repo.StreamWhereAsync(x => x.Price > 0m))
    Process(w);

// Column projection — SELECT only what you need (+ PK).
var summaries = await repo.GetAllAsync(x => x.Id, x => x.Name);

// Optimistic concurrency — IsRowVersion column checked on UPDATE.
try { await repo.UpdateAsync(w); }
catch (ConcurrencyException) { /* row changed under you — reload & retry */ }

// Transient-fault retry — opt-in; deadlocks / dropped connections auto-retried.
var resilient = new DataAccess(new DataAccessOptions
{
    Provider = DbProvider.SqlServer, ConnectionString = cs,
    Retry = new RetryOptions { MaxAttempts = 3 },
});
await resilient.ExecuteInTransactionAsync(async uow => { /* idempotent work */ });

// Dirty reads — WITH(NOLOCK) scope (SQL Server; no-op on Oracle/PG).
using (data.UseDirtyReads())
    var approx = await repo.CountAsync();

// Cross-dialect query composer — provider-portable GROUP BY without raw SQL.
var q = SqlQuery.From<Widget>("w", DbProvider.SqlServer)
    .SelectCols(Widget.Cols.Name)
    .Select(Agg.Count(Widget.Cols.Id, "N"))
    .WhereIf(minPrice is not null, Widget.Cols.Price, ">=", minPrice)
    .GroupBy(Widget.Cols.Name);
var counts = await q.ToDictionariesAsync(data);

4.Strengths & weaknesses

AdDataAccessComponent (legacy)

  • + Very low ceremony: one static call, no object setup
  • + Terse one-liners (Max, Count, Execute(sp, dict))
  • + DataTable/DataSet output binds straight into classic WinForms/WebForms
  • + Battle-tested in production for years
  • − SQL-injection exposure through criteria / PK concatenation
  • − Sync-only; blocks threads under server load
  • − Dead platform: EntLib 5.0 unmaintained; System.Data.OracleClient deprecated
  • − Global static state; effectively untestable in isolation
  • − Per-call reflection + string building + Oracle sequence probing
  • − Int32-only identity / aggregate assumptions
  • − Transaction hand-threaded; Rollback() bug commits instead
  • − No logging, retry, concurrency control, paging, or bulk path

TflOmniDb (new)

  • + Injection-safe by construction; verified by tests on all 3 engines
  • + Async + streaming; scales; cancellable
  • + Three providers behind one API, including PostgreSQL
  • + Testable (interfaces, DI), observable (logging + redaction), resilient (retry, concurrency)
  • + Rich surface: bulk, paging, projection, aggregates, composer, typed SPs
  • + Tooling: scaffolder, migration tool, benchmarks; 800+ automated tests
  • − More initial ceremony (options → DataAccess → repository)
  • − Async-only forces call-chain changes in legacy sync codebases
  • − No DataTable/DataSet bridge for old UI binding (main migration friction)
  • − Explicit SP parameter declaration is wordier than the legacy dictionary
  • − Full-row UpdateAsync differs from legacy null-skip semantics (§3.4)

5.Verdict

TflOmniDb supersedes AdDataAccessComponent on every axis that matters for a banking DAL — security (parameterization vs. a live injection surface), platform viability (supported drivers vs. abandoned EntLib), scalability (async vs. sync), correctness (working rollback, optimistic concurrency, retry), breadth (PostgreSQL, bulk, streaming, paging), and engineering hygiene (tests, logging, tooling). The legacy component's remaining advantages are conveniences — lower ceremony and direct DataTable binding — not capabilities, and the scaffolder plus the migration cheat-sheet absorb most of the porting cost.

The two genuine watch-items when migrating: 1) legacy Update null-skip semantics (§3.4) — audit before porting; 2) DataTable-bound UI code — needs a typed-model or dictionary-row rewrite.
