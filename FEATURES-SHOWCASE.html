TrustBank CBS — .NET 10 Migration : FEATURES DEVELOPED (Showcase)

Strangler-fig migration of TrustBank CBS from WebForms/VB.NET/.NET 4.8 to .NET 10 / C# MVC. One line per feature.

Last updated: 2026-07-30 (post modular-monolith split; 35 solution projects). This is a FLAT capability inventory — it does not say which features are faithful ports of legacy behaviour and which are net-new. For that, read docs/migrated-vs-new.md, which tags every capability Ported / Rebuilt / New and also lists what was deliberately dropped and what is not yet migrated.

To PRESENT any of this: docs/architecture/diagrams/ holds the layered architecture and a features / technologies / components board as .svg (pastes straight into PowerPoint or Word) plus 2x .png copies.

REUSABLE UI COMPONENTS / PICKERS

All partials + client assets ship from the shared RCL TflCbs.Web.Shared (static files served from ~/_content/TflCbs.Web.Shared/), so every host and every screen RCL gets the same components with no duplication.

  • Record Picker (_RecordPicker / RecordPickerModel / cbs-search.js) — Go/Pick/Clear lookup with exact-resolve or modal-browse selection.
  • Account Picker (_AccountPicker / AccountPickerModel / cbs-account-picker.js) — 3-segment account input with a two-stage Chart-of-Account -> Account modal.
  • Date Picker (_DatePicker / DatePickerModel / cbs-datepicker.js) — three-dropdown Day/Month/Year input, leap-year aware, with an ISO yyyy-MM-dd hidden field.
  • Search Modal (_SearchModal / SearchDescriptor) — dynamic filter inputs plus a sortable, paginated grid with row selection.
  • Account Search Modal (_AccountSearchModal) — two-stage Chart-of-Account / Account grids with filter, sort and pagination.
  • RowToken — session-bound, single-use, AES-encrypted opaque row ids that hide primary keys and prevent replay/cross-screen reuse.
  • Notification Modal (_Notification / UserMessage) — blocking acknowledgement modal for Success/Info/Warning/Error outcomes.
  • Transient toast (cbsNotify) — non-blocking client-side guard messages, distinct from the server-outcome ack modal.
  • Action Bar (_ActionBar) — configurable Save/Update/Delete/Search/Cancel form toolbar with primary/ghost styling.
  • Menu surface (_MenuOverlay / _MenuGrid) — server-authorized menu rendering; the menu IS the access-control list.
  • Command palette (_CommandPalette / cbs-command-palette.js) — Ctrl+K quick-access search over the session menu, client-side.
  • Session info bar (_SessionInfoBar) — bank/org, working date + session, financial-year range, last login and screen caption, rendered from session with no per-request DB hit.
  • Unsaved-changes guard (cbs-form-guard.js) — warns on navigating away from a dirty form; declarative data-confirm for destructive actions.
  • Idle timeout (cbs-idle.js + KeepAliveController) — warn at Cbs:IdleWarnMinutes, auto-logout at IdleLogoutMinutes, "stay signed in" ping (GET /Account/Ping -> 204) that closes the b_UserLogTime row on logout.
  • Default-uppercase entry (cbs-uppercase.js) — delegated, caret-preserving, IME-aware uppercasing of text/search/tel inputs; cbs-keep-case opts out on any ancestor, cbs-uppercase opts in elsewhere.
  • Layouts — _Layout (full chrome: menu, session bar, footer marquee) and _LayoutBlank (chrome-free, for login/error).
  • DB Switcher (_DbSwitcher) — development-only selector to switch the active database provider at runtime.
  • Declarative config models — SearchDescriptor / SearchColumn / SearchFilter / SearchRequest / SearchResponse drive search behaviour via config, never client-side SQL.
  • Additive-with-safe-defaults rule — every component extension (e.g. the GET/POST Method opt-in, account-picker host events) defaults to previous behaviour so existing screens are unaffected.
  • Live showcase — /Dev/Components (Development only) renders every component above with dummy data and all options.

ENTITY GENERATION (TflOmniDb.Scaffold)

  • Reverse-engineers live DB schemas into [DbTable]/[DbColumn]-annotated entity classes for SQL Server, Oracle and PostgreSQL.
  • Interactive menu-driven wizard (run with no arguments) plus CLI flags for scripted / CI generation.
  • Configurable namespace, language (C# or VB.NET), target framework (net10 or .NET 4.8) and naming/casing strategy.
  • Emits a nested static Cols token class per entity for type-safe, refactor-friendly SQL composition.
  • Generates partial classes so hand-written business logic survives regeneration in a sibling file.
  • Optional --sensitive flag marks PII columns for automatic redaction in logs and audit trails.
  • Table-prefix filtering (skips "_" tables by default); sources from a live connection or an air-gap SQL dump.

TflCbs.Entities (Generated Domain Entities)

  • 3,682 auto-generated entity classes mirroring the TrustBank CBS database schema 1:1.
  • UPPERCASE nullable properties with type mapping (varchar -> AnsiString, MONEY -> Money, DATETIME -> DateTime, etc.).
  • Every entity inherits Entity, is declared partial, and exposes a nested Cols class of strongly-typed column tokens.
  • Referenced by bare-DLL HintPath to TflOmniDb.dll — build TflCbs.Entities FIRST whenever the schema changes.

TflOmniDb (Data Access Layer / DAL)

  • Repository CRUD — GetAsync / GetAllAsync / InsertAsync / UpdateAsync / DeleteAsync.
  • Set-based operations — UpdateWhereAsync / DeleteWhereAsync / CountAsync with LINQ predicates.
  • DataAccess query API — QueryAsync (POCO), QueryAsync (dictionary), ExecuteScalarAsync, ExecuteNonQueryAsync.
  • Stored-procedure support — ExecuteProcedureAsync with INPUT/OUTPUT/RETURN params and multiple result sets (for legacy procs already migrated as procs; new master CRUD uses Repository).
  • Multi-dialect engine — SQL Server, Oracle and PostgreSQL (identifier quoting, param prefixes, identity, paging, dirty-read hints).
  • Streaming APIs — StreamAllAsync / StreamWhereAsync / StreamQueryAsync / StreamProcedureAsync for arbitrarily large result sets.
  • Fully async-only with CancellationToken support throughout (no synchronous overloads).
  • Transactions & Unit of Work — BeginTransactionAsync, IUnitOfWork, ExecuteInTransactionAsync with transient-failure retry.
  • Optimistic concurrency — row-version columns auto-increment and guard UPDATEs, throwing ConcurrencyException on stale writes.
  • Bulk insert — provider fast paths (SqlBulkCopy / PostgreSQL COPY / OracleBulkCopy) with batching options.
  • Operational scopes — correlation-id tagging, per-scope logging suppression, and sensitivity-based parameter redaction.
  • Attribute-driven metadata — [DbTable]/[DbColumn] capture columns, keys, identity, defaults, foreign keys, row-version and PII flags.
  • Editable in-house source (not a black box) — consumed by HintPath, with its own migration/scaffolding tooling.
  • Full documentation set mirrored at docs/libraries/tflomnidb/ — README, api-reference, usage-guide (21 recipes), components, tooling, the AdDataAccessComponent comparison and a porting cheat-sheet off the legacy Enterprise-Library DAL.

BUSINESS / DATA LAYER (per-domain service modules)

  • Result / Result service contract — every service method returns an outcome envelope; no throwing across the service boundary, no silent failures.
  • No stored procedures and no raw SQL for new master CRUD — everything goes through Repository / DataAccess.
  • Shared query helpers (ServiceQuery: Has / Eq / Val / Paged + page-size bounds) with enforced page-size limits, consumed via using static.
  • Shared DB-error mapping (DbErrors: IsDuplicate / IsForeignKey) — provider-aware duplicate/FK detection instead of per-proc @error codes.
  • Single-definition discipline — SharedServiceHelperTests fails the build if any service re-declares one of those helpers privately.
  • Zero ASP.NET in the data layer — modules reference only TflCbs.Abstractions + TflCbs.Entities/TflOmniDb, so the same services run in any host or console tool.
  • Proc-parity perf harness — times a legacy T-SQL proc against its migrated C# service across three targets and writes a dated report (docs/perf/).
  • Conversion pipeline — every proc is converted in TflCbs.Lab first, then promoted (class-wise or function-wise, Roslyn-assisted) into its owning module assembly.

MODULAR MONOLITH & FRAMEWORK

  • Vertical split COMPLETE (2026-07-29) — nine independently-buildable service assemblies; the interim single TflCbsServices assembly no longer exists.
  • Core modules (ICoreCbsModule, always registered) — TflCbs.Modules.General (menu, bank variables, broadcast/alerts, maker-checker scroll, process-block check), TflCbs.Modules.Reference (geography masters), TflCbs.Core.Authentication (login, credential and session rules).
  • Domain modules (gated by Modules:Enabled) — HR, Lockers, Accounts, Clearing, Administration, RetailBanking; module = bounded domain, never per-service.
  • Dependency-free foundation — TflCbs.Abstractions holds Result/Result, ICbsModule/ICoreCbsModule, the four framework ports, the boundary DTOs and the shared service helpers; no TflCbs.Entities, no TflOmniDb, no ASP.NET.
  • Framework ports (IBroadcastSource / IBankVariableSource / IMenuSource / ISessionValidator) — modules implement, the framework consumes, with no-op defaults so a partial composition still boots.
  • Published cross-module contracts — TflCbs.Modules.General.Contracts (IScrollService / ScrollSources, IProcessBlockCheck); consumers never reference General's implementation.
  • Reference-module admission rule — a master joins TflCbs.Modules.Reference only if it has no domain behaviour AND >=2 domains consume it, so it cannot become a dumping ground.
  • Explicit module composition — AddCbsModules(config, ) with no implicit anchor; unknown names in Modules:Enabled fail loud at startup.
  • Deployed-module cross-check — startup throws if a TflCbs.Modules. / TflCbs.Core. assembly is present in the output directory but was not handed to AddCbsModules (nothing else catches that mistake).
  • Per-domain web RCLs — screens ship as composable Razor Class Libraries (TflCbs.Modules..Web) the host adds via gated AddApplicationPart; only hosts that enable a module reference it.
  • Horizontal framework/screen split — TflCbs.Framework references only TflCbs.Abstractions: never a service module, never a screen RCL (compiler-enforced and arch-tested).
  • Namespace == assembly across the whole solution, so a using names the assembly you are coupling to; enforced by NamespaceDisciplineTests with zero exceptions.
  • One-call framework setup — AddCbsFramework() + UseCbsFramework() wire session, cache, fail-closed access guard, search, DataAccess, health checks and security headers.
  • CbsScreenController — shared base for CRUD controllers: string-only token helpers (TryOpenRecord/TryBeginWrite/TryConsume/ProtectId), SavedOk/UpdatedOk/DeletedOk, TryLoad, EditFailed, RunSearch.
  • Server-owned search — SearchEndpoint + SearchRequest/SearchResponse; no SQL, table or column names ever reach the client (the legacy encrypted-SQL-in-the-URL model is gone).
  • Per-action attribute routing — each CRUD operation is its own routed action (compile-checked via asp-action/@nameof) instead of magic-string command dispatch.
  • Route cutover — a_Menus.NavigateURL holds each screen's route; a DbMigrator migration rewrites it from the legacy *.aspx at cutover (strangler-fig, one source of truth for both the link and the access set).
  • Multi-provider wiring — DatabaseSelector + ADO.NET driver registration for SQL Server / Oracle / PostgreSQL from a single config switch.
  • Health checks — DatabaseHealthCheck plus per-host endpoints for gateway probing.

SECURITY, AUTHENTICATION & SESSION

  • Fail-closed access — CbsAccessMiddleware allows a route only if the user is authenticated, has a module selected, and the URL is in their server-side menu; per-screen [CbsAccessScreen] binds sub-routes to their owning screen's rights.
  • Per-request single-session guard — force-logout of a superseded session (legacy IsUserAlreadyLoggedIn behaviour, preserved).
  • Financial-year readiness gate — required by default, opt out with [CbsSkipFinancialYearCheck]; a missing FY redirects to login with a visible reason instead of a silent bounce.
  • Stale-session recovery — b_UserLogTime.LoginInfo carries so a user's own dead session from the same workstation is cleared before the "already connected" gate; parsed only by LoginInfo, the one sanctioned parser.
  • PBKDF2 password storage — per-user salt in PASSWORDHASH/PASSWORDVERSION, replacing the legacy reversible scheme; one-off clean-break migration via TflCbs.Tools.PasswordReset (supports --dry-run).
  • Password policy + expiry alerts — PasswordPolicyRules and a password-expiry notice surfaced on the module chooser.
  • Three-clock idle policy — client warn/logout thresholds and the server session TTL must agree; CbsSessionOptions.Resolve refuses to start if the server TTL does not exceed the client logout.
  • Security response headers — CSP, X-Frame-Options and friends, applied first in the pipeline.
  • Antiforgery on every mutating post, covered by an integration test.
  • Opaque row identity — RowToken keeps real primary keys off the client entirely (AES, screen+session bound, single-use on write).
  • Connected-user administration — /Administration/ConnectedUsers over ConnectedUserService.
  • Secrets hygiene — no credentials or connection strings in source; appsettings.Development.json is gitignored and never published; production supplies the connection string via environment variable / secret store.
  • TflSecurityCrypto — see the next section (byte-for-byte legacy crypto compatibility).

TflSecurityCrypto (Cryptographic Utilities)

  • Salted hashing — SimpleHash ComputeHash / VerifyHash across MD5, SHA1, SHA256, SHA384 and SHA512.
  • Symmetric encryption — Triple-DES (3DES) block cipher and an RC4 stream cipher with base64 output.
  • Salt-hash password handling — SHA256-plus-salt scheme with matching verify, plus the PBKDF2 PasswordHash used by the new login.
  • Hardware fingerprinting — machine-bound licensing from WMI motherboard / CPU / disk serials (Windows).
  • Cryptographically secure RNG — RNGCSP for uniform, unbiased random generation.
  • Legacy 1:1 VB.NET port — byte-for-byte cryptographic output compatibility with the original library.
  • Full documentation set mirrored at docs/libraries/tflsecuritycrypto/ — README (incl. how the compatibility guarantee is proven), api-reference and primitive-by-primitive security notes.

CACHING (Reference Cache)

  • Generic IReferenceCache for slow-changing master data — category+id keyed, read-through, with a generation-token "flush all".
  • Per-key stampede guard plus a TTL backstop; fail-open by design (a cache error transparently falls back to the DB loader, never throws).
  • Provider chosen by Cache:Provider — in-memory default (the app runs fully with nothing configured), Redis, SQL Server, or bring-your-own IDistributedCache.
  • Bank/branch variables served through IBankVars with a per-request memo, replacing the old per-user session snapshot — so an admin flush reaches logged-in users on their next request with no re-login.
  • Removing those session Hashtables also removed the last non-serializable session state, unblocking future session externalization.
  • Access-guarded, audited admin screen /Bank/ReferenceCache — inspect category/id/size/timing, flush one entry or all (sizes only, never values).
  • Broadcast/marquee caching — the bank-wide broadcast is loaded once with a short TTL, not per user per request.

LOGGING (TflOmniLog)

  • Reusable Serilog-backed logging component (ITflLogger / ITflLogger) with terse Trace/Debug/Info/Warn/Error/Critical, kept ASP.NET-free so the data layer can use it.
  • Category-wise logging — every line carries a Category, and categories flagged SeparateFile fan out to their own rolling file (audit / security / performance).
  • Config-driven levels — global minimum plus per-category level and enable/disable, hot-swappable at runtime via IOptionsMonitor.
  • Audit API — who / what / when / before-after into a dedicated trail.
  • PII masking — recursive redaction of AccountNo/PAN/CVV/password-style values, plus configurable regex/value patterns; masks values, not literal template text.
  • Correlation — ambient TflLogContext reusing Activity.Current.Id; cross-host enrichment (UserId/UserName/SessionId/Host) for multi-host tracing.
  • Sinks — file, console, batched SQL Server (ILogRowWriter seam + sql/CbsLog.sql) and alert-on-Critical (webhook/SMTP via IAlertChannel, throttled).
  • Sampling / rate limiting — token-bucket per level+category+template, annotating dropped counts rather than lying about volume.
  • TflOmniDb integration without coupling — a CategorySources map routes TflOmniDb's SQL logs to the Database category (and its own file/level) while TflOmniDb stays MEL-only, with no Serilog dependency.
  • TimeOperation perf timing, and an HTTP request-logging middleware in the framework (Request category) so the core stays ASP.NET-free.

OBSERVABILITY (OpenTelemetry)

  • One-call AddCbsObservability — OpenTelemetry traces and metrics with ASP.NET Core, HTTP-client and .NET runtime instrumentation.
  • OTLP export to a pluggable backend; the dev backend is the single-container grafana/otel-lgtm stack (compose.observability.yaml, Grafana on :3000).
  • Enabled per host, so a request crossing the gateway into a thin host is traceable end to end.

MULTI-HOST & SINGLE SIGN-ON

  • Internal cross-host SSO — log in once, recognized on every CBS host (CbsAuth encrypted cookie; no external IdP/SAML/OIDC).
  • Shared DataProtection key ring in the DB (CBS_DATAPROTECTIONKEYS) — any host decrypts a cookie any other host issued.
  • Global logout — shared revocation table (CBS_SESSIONREVOCATIONS) kills a session across all hosts.
  • Per-host session rehydration — a jumped-to host rebuilds the session from the cookie ticket and reloads its own menu from the DB.
  • YARP gateway (TflCbs.Gateway, :5100/:7100) — one origin fronting all hosts: path routing, health checks, load balancing, rate limiting. Pure proxy: no framework, no screens, no project references.
  • Four thin per-module hosts — Hr (:7300), Lockers (:7200), RetailBanking (:7400), Administration (:7500) run one domain + core standalone.
  • Login authority — an absolute external Auth:LoginUrl defers login to the designated authority host; ForwardedHeaders:Enabled keeps returnUrl on the gateway origin.
  • Permanent HTTPS dev topology — plain dotnet run per project brings the cluster up; the default host joins via the https (shared-sso) launch profile.

DEPLOYMENT & BUILD

  • Four supported deployment shapes — IIS single-host, IIS multi-host (gateway + thin hosts), Docker single-host, Docker multi-host — all driven by scripts/deploy-cbs.ps1 (cbs-deploy skill).
  • Docker assets — Dockerfile plus compose.yaml (1 container), compose.multi.yaml (6 containers, only the gateway port published), compose.multi.https.yaml and compose.observability.yaml.
  • IIS automation — deploy-cbs-iis.ps1 provisions sites/app-pools and writes per-site web.config for connection string, SSO key ring and gateway login URL.
  • Dev cluster scripts — start-cbs-hosts / stop-cbs-hosts (.ps1 + .bat).
  • Central Package Management — every NuGet version in Directory.Packages.props, version-less PackageReference in csprojs; solution-wide defaults (net10.0, nullable, implicit usings) in Directory.Build.props.
  • Publish hygiene — appsettings.Development.json is marked CopyToPublishDirectory=Never so local dev credentials cannot reach an artifact.

TESTING & QUALITY GATES

  • TflCbs.Tests (xUnit) — cross-provider, non-destructive service tests across all nine service modules.
  • TflCbs.ArchTests (NetArchTest) — ten suites enforcing framework-vs-screens isolation, web-module boundaries, namespace == assembly, module config gating, the promoted-module list, guard ordering, session-timeout coherence, reference-cache rules and resolve-all-modules.
  • TflCbs.IntegrationTests (Mvc.Testing) — boots the real host pipeline in-process, middleware order included, and asserts the fail-closed access guard, antiforgery and authenticated access.
  • TflOmniLog.Tests — unit tests for the logging library.
  • TflCbs.Demo — console mirror of every service method against any provider, kept in step with the tests by the cbs-sync-test-demo agent.
  • Build-failing conventions — a privately re-declared shared service helper, a namespace/assembly mismatch or an incoherent idle-timeout configuration all fail the build or startup rather than degrading silently.
