================================================================================
  2 · ROWTOKEN PAYLOAD — WHAT'S INSIDE THE OPAQUE STRING
================================================================================

   screen | sid | jti | id           (id placed LAST - it may itself contain '|')
     |       |     |     +- the real PK (string: int / GUID / code)
     |       |     +------ jti = Guid.NewGuid()  -> the single-use nonce
     |       +------------ sid = current session GUID  -> dies on logout / rotation
     +-------------------- screen = "Hr/State"        -> no cross-screen reuse

        _protector.Protect(...)  ->  AES encrypt + sign  ->  opaque token (to client)
        (confidentiality + integrity + managed key rotation;  PK hidden, unforgeable)

   GUARANTEE BY FIELD
   ------------------
     screen  ->  a token minted on Hr/State can't be replayed on another screen
     sid     ->  bound to the live session; dies on logout / session rotation
     jti     ->  makes WRITE tokens single-use (replay + double-submit blocked)
     id      ->  the raw primary key never leaves the server

  3 · ROWTOKEN LIFECYCLE — MINT -> RESOLVE -> CONSUME
================================================================================

 MINT  (during search Build, see S1)                       RowToken.cs:24
 -----------------------------------
   tokens.Protect(idStr, "Hr/State")
        |  sid = store.CurrentSessionId ;  jti = Guid.NewGuid("N")
        v
   AES-encrypt "Hr/State|sid|jti|123"  -->  token  -->  row["Id"]  -->  JSON to client
                                                                          (raw PK 123 hidden)

   --- client holds the token only; sends it back as ?row=<token> or Form.Row=<token> ---


 RESOLVE  (READ paths - validate only, nonce NOT spent)    RowToken.cs:33
 ------------------------------------------------------
   Index(?row=token)  /  EditFailed / Delete-reopen
        |  tokens.TryResolve(token, "Hr/State", out id)
        v
   TryRead():  Unprotect (decrypt)         -- fail -> tampered / wrong-key  --+
        |      split into 4 parts          -- fail -> malformed              --+
        |      parts[0] == screen?         -- no   -> cross-screen reuse     --+--> FALSE
        |      parts[1] == CurrentSessionId? -- no -> expired / other session--+     -> NotifyError
        v                                                                            "link invalid/expired"
   id = parts[3]  ->  int.TryParse  ->  load record  ->  render edit form
        (edit form re-mints a fresh token: vm.Form.Row = tokens.Protect(id, screen))


 CONSUME  (WRITE paths - single-use)                       RowToken.cs:36
 -----------------------------------
   Update / Delete  (POST)
        |  tokens.TryConsume(form.Row, "Hr/State", out id)
        v
   TryRead(... out jti)  -- invalid -------------------------------> FALSE -> NotifyError
        | valid                                                             "reopen the record"
        v
   store.TryConsumeRowToken(jti)                              CbsSessionStore.cs:45
        |  lock(ConsumedRowTokens)  return set.Add(jti)
        |      +- jti new   -> Add == true   -> proceed with Update / Delete
        |      +- jti seen  -> Add == false  -> "already submitted" (replay / double-click blocked)
        v
   perform write (svc.UpdateStateAsync / DeleteStateAsync)
   (ConsumedRowTokens set is session-scoped, cleared on logout)


 READ vs WRITE
 -------------
   +------------------------------+--------------+----------------+-------------------------------+
   | Path                         | Method       | Touches nonce? | Why                           |
   +------------------------------+--------------+----------------+-------------------------------+
   | Read (Index, reopen)         | TryResolve   | No             | reopen any number of times    |
   | Write (Update, Delete)       | TryConsume   | Yes (adds jti) | single-use: replay/double-sub |
   +------------------------------+--------------+----------------+-------------------------------+

   Update validates the token FIRST via TryBeginWrite (so a ModelState failure re-renders
   the form WITHOUT burning it) and only TryConsume's once the write proceeds.
   -> StateController.cs:89 (validate)  and  :94 (consume)
   TryBeginWrite / TryOpenRecord are the CbsScreenController wrappers over
   RowToken.TryResolve.


  NOT ACCESS CONTROL
  ------------------
  Tokens secure the HANDOFF (PK confidentiality + integrity + single-use).
  Authorization is still enforced separately by CbsAccessMiddleware (menu/route
  guard) and the scoped service calls. A valid token is never a substitute for
  being allowed on the screen.
